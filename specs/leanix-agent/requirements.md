# CONN-LEANIX-AGENT — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-LEANIX-AGENT-R001` | **Per-operation tools.** The server must serve one typed tool for every operation id in its 31 routers, 746 ids in total. | `tests/test_per_operation_tools_cover_routers.py` rows R001.1 to R001.6 pass. |
| `CONN-LEANIX-AGENT-R001.1` | **Operation inventory.** The service clients in `leanix_agent/api` must list 31 domains holding 746 public operation methods. Caller chain: the `leanix-mcp` console script (`scion_sdk.cli:serve`) loads `leanix_agent:connector` (`leanix_agent/__init__.py:94`), whose `tools="leanix_agent.mcp_server"` module imports the `register_leanix_*_tools` registrars that SDK `build_server` runs into `register_tool_surface`. Shape: each `leanix_agent/api/api_client_<domain>.py` defines an `Api` class whose public methods are the operations; the test reads them with `ast` in `_router_operation_ids`. | `tests/test_per_operation_tools_cover_routers.py::test_router_inventory_is_complete` must pass. |
| `CONN-LEANIX-AGENT-R001.2` | **Every id has a tool.** Each operation id must map to a tool named `leanix_leanix_<domain>_<id>` in the served set. Caller chain: the `leanix-mcp` console script (`scion_sdk.cli:serve`) loads `leanix_agent:connector` (`leanix_agent/__init__.py:94`), whose `tools="leanix_agent.mcp_server"` module imports the `register_leanix_*_tools` registrars that SDK `build_server` runs into `register_tool_surface`. Shape: the SDK splits each `_<DOMAIN>_ACTIONS` router into one typed tool per id; the test reads served names with `scion_sdk.mcp.tool_surface.registered_tools` over `build_server("leanix_agent")`. | `tests/test_per_operation_tools_cover_routers.py::test_every_old_router_operation_id_has_a_tool` must pass. |
| `CONN-LEANIX-AGENT-R001.3` | **No dispatcher tool.** The server must not serve a per-domain tool that routes an `action` argument. Caller chain: the `leanix-mcp` console script (`scion_sdk.cli:serve`) loads `leanix_agent:connector` (`leanix_agent/__init__.py:94`), whose `tools="leanix_agent.mcp_server"` module imports the `register_leanix_*_tools` registrars that SDK `build_server` runs into `register_tool_surface`. Shape: no router-level tool named `leanix_leanix_<domain>` may stay in the set returned by `registered_tools`; the SDK per-operation split replaces the dispatcher in `leanix_agent/mcp/_action_dispatch.py`. | `tests/test_per_operation_tools_cover_routers.py::test_no_router_tool_remains_as_an_action_dispatcher` must pass. |
| `CONN-LEANIX-AGENT-R001.4` | **Shared SDK floor.** The package must require `scion-sdk[mcp,graphql]>=0.9.0,<1.0.0` in `pyproject.toml`, because the SDK serves one typed tool per client method of each declared service client. Caller chain: the `leanix-mcp` console script (`scion_sdk.cli:serve`) loads `leanix_agent:connector` (`leanix_agent/__init__.py:94`), whose `tools="leanix_agent.mcp_server"` module imports the `register_leanix_*_tools` registrars that SDK `build_server` runs into `register_tool_surface`. Shape: the `dependencies` list in `pyproject.toml` line 12 carries `scion-sdk[graphql,mcp]` with a range; the test parses it with `packaging.requirements.Requirement`. | `tests/test_per_operation_tools_cover_routers.py::test_sdk_floor_is_declared_for_the_split_surface` must pass. |
| `CONN-LEANIX-AGENT-R001.5` | **Wiring.** `leanix_agent/__init__.py` must declare one `verbose_targets` entry per service client in `OPERATION_DOMAINS`, which the SDK `build_server` passes to `register_tool_surface` for every server start. Caller chain: the `leanix-mcp` console script (`scion_sdk.cli:serve`) loads `leanix_agent:connector` (`leanix_agent/__init__.py:94`), whose `tools="leanix_agent.mcp_server"` module imports the `register_leanix_*_tools` registrars that SDK `build_server` runs into `register_tool_surface`. Shape: `leanix_agent/mcp_server.py` is 205 lines and only imports and re-exports the registrars in `__all__` (the row line 234 no longer exists); the SDK `build_server` discovers them with `vars(module)` and calls `register_tool_surface`. | `tests/test_per_operation_tools_cover_routers.py::test_client_lists_every_operation_tool_through_the_real_server` must reach that call. |
| `CONN-LEANIX-AGENT-R001.6` | **Hot-path proof.** An MCP client connected to the production server object must list 758 tools, including every router operation tool. Caller chain: the `leanix-mcp` console script (`scion_sdk.cli:serve`) loads `leanix_agent:connector` (`leanix_agent/__init__.py:94`), whose `tools="leanix_agent.mcp_server"` module imports the `register_leanix_*_tools` registrars that SDK `build_server` runs into `register_tool_surface`. Shape: the test connects a fastmcp `Client` to the object from `build_server("leanix_agent", command_args=[])` and compares `list_tools` with the `leanix_leanix_<domain>_<id>` set built from `_router_operation_ids`. | `tests/test_per_operation_tools_cover_routers.py::test_client_lists_every_operation_tool_through_the_real_server` must pass. |
| `CONN-LEANIX-AGENT-R002` | **Shared GraphQL client.** GraphQL calls go through the shared SDK client. GraphQL and the query-language core come only from the shared SDK `graphql` extra, so direct `graphql` imports resolve from it. Caller chain: a LeanIX GraphQL tool in `leanix_agent/mcp/mcp_graphql.py` obtains the client from `get_graphql_client` (`leanix_agent/auth.py`, constructs `GraphQL` at line 274) -> `GraphQL` in `leanix_agent/leanix_gql.py:76` -> SDK `scion_sdk.transports.graphql.GraphQLClient`. Shape: `GraphQL` in `leanix_agent/leanix_gql.py` wraps the SDK `GraphQLClient` and `GraphQLAuth`, takes trust from `resolve_tls_profile`, and maps `GraphQLExecutionError` to the unchanged message; `pyproject.toml` takes `graphql` only from the `scion-sdk[graphql]` extra. | `tests/test_leanix_gql.py::TestGraphQLDelegation` must pass. |
